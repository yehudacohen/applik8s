---
title: v0.8 to v0.9 migration
description: Understand the read-only proposal and why mutation remains disabled in alpha.1.
---

v0.9 alpha.1 can produce a deterministic, read-only migration proposal. It cannot mutate deployment state.

The proposal requires the exact released v0.8 package, tag, graph and plan schemas, provider-catalog digest,
runtime protocol versions, and evidence manifest. That release baseline is not currently available, so the
foundation emits `V09_BASELINE_RELEASE_UNAVAILABLE` and keeps `mutationAuthorized: false`.

The proposal maps each legacy node by semantic identity and canonical physical identity, then explains one
of: preserve, adopt, replace, retire, retain, or external. Ambiguity, provider incompatibility, unsafe
ownership, and retained-data drift remain blocked.

Do not use source-candidate state as a substitute for an exact release baseline.
