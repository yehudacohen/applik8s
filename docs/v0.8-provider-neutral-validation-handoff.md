# v0.8 provider-neutral validation handoff

This handoff is for clean external applications validating Applik8s v0.8. It
contains no product schemas, migrations, workflows, or private architecture.
Those remain application-owned.

## Public contracts to validate

| Need | Public surface | Framework-owned guarantee |
| --- | --- | --- |
| Request admission | `@applik8s/core/admission` and maintained gateways | One validated principal, authority version, and trusted-context boundary with domain-specific narrowed views. |
| Commands, queries, streams, tasks, workflows, schedules, and actors | `@applik8s/applik8s` plus selected runtime packages | Typed payload and lifecycle semantics remain domain-owned while shared integrity, causality, authority, and provider injection are framework-managed. |
| Relational, Kubernetes, search, projection, object, and lakehouse data | model/query/projection/object/lakehouse APIs and selected providers | One authored application graph, target-specific planning, bounded access, explicit compatibility diagnostics, and retained provider-neutral identities. |
| Provider accounting and telemetry | `@applik8s/usage`, `@applik8s/runtime-otel` | Admitted-scope accounting and causal telemetry without application-owned signing or transport glue. |
| Bounded public-web retrieval | `@applik8s/web-search` | Typed result provenance, bounded query/result/deadline/response behavior, deterministic local execution, and no ownership of application evidence policy. |
| Managed or external SearXNG | `@applik8s/web-search-searxng` | Reference-only Secret configuration, HTTPS-by-default external transport, TypeKro-managed Kubernetes topology, and the same callable `webSearch.search(...)` surface. |

The ordinary web-search call is intentionally small:

```ts
import { WebSearch } from '@applik8s/web-search';

const ResearchWeb = WebSearch.named('research');
const webSearch = application.inject(ResearchWeb);

export async function findSources(query: string) {
  return webSearch.search({
    query,
    limit: 8,
    safeSearch: 'moderate',
    timeoutMs: 10_000,
  });
}
```

Applications own source policy, evidence records, citations, disclosure,
classification, retries above the provider boundary, and product accounting.

## Clean-consumer checks

Run against the exact coordinated v0.8 package set or source commit:

```sh
bun run check:v08:runtime-integrity
bun run check:v08:provider-conformance
bun run check:v08:target-parity
bun run check:packages
```

Then validate the application-specific source package without private runtime
imports or local patches:

1. compile direct calls and stable extracted provider operations through every
   maintained execution family the application uses;
2. run the deterministic provider differential fixtures first;
3. generate each claimed target plan and verify unsupported combinations fail
   before mutation;
4. deploy only the selected live providers, exercise retry and cancellation,
   and tear them down through their Applik8s/Alchemy/TypeKro lifecycle owner;
5. verify persisted compatibility using the release's declared readers and
   writers rather than recreating signing, cursor, or canonicalization code.

## Current limitations

- Local and AWS Agentic Start profiles use deterministic WebSearch unless the
  application explicitly supplies another target-qualified provider. The
  maintained Kubernetes branch selects SearXNG.
- Managed SearXNG requires an existing Secret containing `secret_key` (or the
  configured key). Secret values never belong in the ApplicationGraph or
  installation YAML.
- Strict TypeKro planning of that reference-only topology requires the TypeKro
  fix tracked in [upstream PR #166](https://github.com/yehudacohen/typekro/pull/166). Until it is released and consumed, managed
  SearXNG is implemented but not live-qualified in the release evidence.
- AWS-local is API-fidelity evidence, not real AWS lifecycle, IAM, telemetry,
  performance, or cost evidence.

Report a discovered framework defect as the smallest public reproduction:
package versions or commit, target/profile, public graph fixture, expected
contract, observed diagnostic, and cleanup receipt. Do not include application
secrets or private product design.
