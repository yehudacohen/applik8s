# v0.6 Foundation Boundaries

Applik8s v0.6 implements the native-model and reactive-application layer described by the vision while
keeping provider-specific guarantees explicit.

- Drizzle is the schema authority for native relational models. Promoted tables remain usable by Drizzle
  and gain derived ArkType select/insert/update schemas plus the common Applik8s model facet.
- PostgreSQL is the first relational provider. Generated migrations install the application schema,
  framework command/history/outbox tables, change-log indexes, RLS policies, and idempotent migration
  history under an advisory lock.
- Trusted context is admitted once, carried through cursor/replay boundaries, and enforced by PostgreSQL
  RLS. Pooled connections clear admitted context on success, rollback, and reuse.
- Public queries use authoritative snapshot plus resumable invalidation. The framework does not infer
  row-level deltas from arbitrary SQL.
- Durable streams expose bounded, authorization-aware replay. ClickHouse projections use idempotent
  writes and durable checkpoints, and support explicit rebuild semantics.
- The browser client, framework-neutral store, React hooks, and TanStack Start adapter are browser-only
  dependency zones. Kubernetes, TypeKro, compiler, SDK, and Node imports fail the module-boundary gate.
- `@applik8s/vite` is the framework boundary: it discovers the graph, produces environment-specific
  facades, generates the standard Fetch gateway, and rejects server-only dependencies in browser
  chunks. `@applik8s/tanstack-start` only mounts and hydrates those contracts.
- Kubernetes query authorities capture a bounded list `resourceVersion`, continue watches from that
  frontier, convert object changes into invalidations, and reset on compaction. The Kubernetes SDK stays
  in the server artifact; it is not bundled into the browser or operator WASM by this application-host
  path.
- `ApplicationHost.kubernetes(...)` copies digest-verified Vite output into an OCI build context and
  emits Deployment, Service, ServiceAccount, inferred RBAC, probes, stable external cursor-Secret
  binding, and image provenance. Vite builds remain side-effect free.
- Generated gateways, projection workers, migrations, network policy, database infrastructure, and
  ClickHouse infrastructure are graph-visible artifacts with bounded readiness and lifecycle evidence.
- A generated gateway binding can be passed directly to `app.expose(...)`; its generated Service name,
  namespace, and port remain one compiler-owned identity. Managed TLS and DNS still require explicit
  cert-manager and ExternalDNS provider bindings and never imply controller installation or propagation.

Exactly-once behavior is not claimed across providers. Ordinary database writes outside the observable
transaction boundary require explicit invalidation/reset or a future CDC provider. PostgreSQL,
ClickHouse, Kubernetes, and browser caches retain their native consistency models; the common model facet
does not erase those differences.

## KRO 0.9 lifecycle boundary

KRO 0.9 deletes Job resources without a background propagation policy, so Kubernetes can preserve their
completed Pods. KRO's instance-propagation control is not part of the released API used by v0.6.
Applik8s destroys the scoped Alchemy transaction, whose TypeKro resources perform supported instance,
definition, and Namespace teardown. It never substitutes raw resource, RGD, CRD, Namespace, or finalizer
mutation for the owning factory. TypeKro 0.31.1 gates cleanup on the owner CR and concrete children reaching
absence, removes the RGD only after that proof, and then completes graph-owned Namespace cleanup. Its
generated CRD intentionally remains `Active` for reuse; the live lane proves that it is KRO-labeled and
contains no instances after teardown.

Generated-CRD garbage collection is therefore an explicit cluster-administration concern, not application
lifecycle or test hygiene. The prerelease harness does not delete the retained CRD or clear its finalizers,
and a lifecycle timeout remains a failed test with the RGD left available for a safe TypeKro retry.
