# v0.6 scorecard

The executable v0.6 gate is `bun run check:v06:local`. It requires type/lint/module/package gates,
character coverage, Rust formatting and Clippy, host and bridge contracts, real
ComponentizeJS/WIT/Wasmtime invocation, plus focused native compatibility, common model context,
PostgreSQL transaction/migration, gateway/client, stream replay, ClickHouse projection, React/TanStack
integration, framework-neutral Vite facade/gateway generation, immutable ApplicationHost lowering, and
graph validation tests.

Release evidence is split honestly:

- local and packed-consumer gates prove API/type/package/runtime boundaries without workspace aliases;
- PostgreSQL integration proves RLS, locking, rollback, duplicate recovery, and observable change order;
- the explicit OrbStack prerelease lane proves TypeKro lifecycle, migration Job, gateway/processor
  readiness, provider restart, and cleanup through the owning factory;
- the GuestBook receipt proves the full Vite/Start/ApplicationHost path from callable browser command
  through Kubernetes creation and operator moderation to SSE invalidation, authoritative requery, SSR,
  restart recovery, runtime-created data cleanup, and TypeKro-owned deletion;
- the tracked synthetic-local history records cache-key latency/throughput/RSS plus finite projection replay
  cold start, lag, convergence, throughput, and RSS without representing those numbers as datastore or
  cluster performance; and
- a separate full-Chirp build history records browser gzip, server output, RGD size, web/compiler wall time,
  and every generated OCI context with Git/worktree and hardware identity.

Application deletion is always initiated and awaited through the TypeKro factory. The harness does not
raw-delete generated children, RGDs, CRDs, Namespaces, or finalizers. A successful live receipt proves the
application root, concrete children, RGD, app-owned direct preparation, and Namespaces are absent, while the
KRO-generated application CRD remains `Active`, empty, and labeled for reuse as TypeKro 0.28 specifies.
Generated-CRD garbage collection is a separate administrative operation. See
[v0.6 Foundation Boundaries](./v0.6-foundation.md#kro-09-lifecycle-boundary).

The scorecard does not award evidence for a graph-only declaration or infer exactly-once behavior across
providers. A missing live environment is reported as missing release evidence, not converted into a pass.

Run `bun run check:v06:prerelease:orbstack` for release-candidate evidence. The lane refreshes real
PostgreSQL and ClickHouse receipts, deploys a generated TypeKro application on OrbStack, proves tenant
isolation, query invalidation, public-stream replay, durable ClickHouse projection, restart/resume, and
factory-owned deletion, then runs `scripts/check-v06-scorecard.ts --require-live`. Receipts live under
the ignored `.applik8s-tmp/evidence/v0.6/` directory, expire after 24 hours, and are evidence only for
the current machine and cluster—not tracked substitutes for CI results.

Record the two local histories with:

```sh
bun run benchmark:v06:record
bun run benchmark:v06:chirp-artifacts:record
```

The current reports are [the synthetic runtime baseline](../benchmarks/v0.6/baseline.json) and
[the Chirp artifact baseline](../benchmarks/v0.6/chirp-artifacts/baseline.json). Source maps remain separate
compiler/debug artifacts, exclude embedded source content, and are not copied into runtime images unless an
internal caller opts in explicitly. This keeps the image boundary smaller without pretending the recorded
context bytes are compressed layer or registry-transfer sizes.
