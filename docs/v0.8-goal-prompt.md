implementation goal.

```text
Continue the Applik8s v0.8 implementation in the active v0.8 worktree and deliver
the complete accepted program in docs/v0.8-execution-plan.md, the v0.8 manifesto,
all v0.8 RFPs, docs/v0.8-scorecard.json, docs/v0.8-acceptance.json, and
docs/v0.8-target-compatibility.json.

Treat docs/v0.8-execution-plan.md as the authoritative implementation sequence.
Use its evidence-state taxonomy, dependency lanes, and per-slice definition of
done. Do not report implementation as integration or live qualification. Update
the reconciliation ledger and machine-readable scorecard at every evidence-state
transition with the exact commit, command, environment, artifact, and cleanup
result. Maintain the plan's compact per-slice evidence record and obey its risk
stop rules at the earliest affected boundary; pause only dependent work rather
than weakening a gate or unnecessarily serializing independent lanes.
Preserve all unique existing work. Verify the recorded v0.8 checkpoint series and
push it before rebasing or changing history. If remote push is blocked by missing
authority or the environment, preserve the existing commits, do not rewrite them,
record the external blocker, and continue only with additive work that does not
depend on rebasing. Reconcile the maintained v0.7.x release work, focused
typed-HTTP-to-workflow branch, older worktrees, and known compatibility patches
through an explicit finding-to-fix-to-test ledger. Never port patched dist files
or merge stale branches wholesale.

Keep the narrow typed-HTTP-to-function-native-workflow fix independently
reviewable and releasable on v0.7.x. It must inject provider-neutral workflow
handles and selected runtime dependencies, preserve authority/idempotency/
causation/cancellation/reattachment, reject dynamic undeclared workflow identities,
and prove lost-response retry produces one workflow run and one effect.
Require clean packed-consumer generation and emitted-worker retry/reattachment
evidence before calling that candidate integrated. If exact live Hatchet evidence
is unavailable, keep the candidate reviewable and mark the live claim externally
blocked rather than weakening the test or blocking unrelated v0.8 lanes.

After rebasing v0.8, complete the Runtime Integrity foundation before expanding
more provider implementations:

1. Define Canonical JSON v1 with named domain policies and explicit TypeKro/CEL
   adapters.
2. Replace duplicated HMAC/base64url/cursor code with one versioned,
   purpose-separated signed-envelope substrate and Node/WebCrypto adapters.
3. Replace repeated principal/authority/trusted-context admission shapes with one
   validated canonical admission context consumed through narrowed views. Keep
   docs/v0.8-admission-adapter-matrix.json exhaustive and make its parity/source

   rows without exact regressions.
4. Add fixed vectors, differential runtime evidence, legacy migration where
   genuinely required, and source gates preventing duplicated crypto from
   returning.

Follow the normative consolidation ownership map in
docs/v0.8-execution-plan.md. Share mechanics, not domain meaning: Runtime
Integrity owns cryptographic and canonical-byte machinery; core owns canonical
admission validation; search keeps provider continuation semantics; each
execution family keeps its payload and operation authorization. Do not complete
the refactor by moving duplicated code behind another internal import. The public
package graph must remain acyclic, clean consumers must not rely on workspace
hoisting, and provider/application code must not import internal runtime
implementations.

Maintain `docs/v0.8-format-registry.json`, the checked-in persisted-format registry
required by the execution plan.
For every envelope, cursor, digest, admission record, deployment artifact, and
durable record, record reader/writer versions, lifetime, purpose/key namespace,
migration phase, telemetry, rollback window, and removal release. Prove migrations
restart safely at interrupted boundaries and that the documented previous release
can read state written during the rollback window.

Follow docs/adr-v08-runtime-integrity-package-ownership.md: core owns canonical
bytes and wire validation, runtime owns portable asynchronous signing and
verification, execution packages own typed payloads only, and compiler/TypeKro
integration owns explicit reference adapters. Use a three-release rolling
migration for durable formats unless an exact record proves mixed readers/writers
cannot coexist. Keep the runtime-integrity scorecard gate false until its real
command and migration evidence pass.

Then implement callable provider injection. application.inject() must return a
typed callable provider handle/proxy whose runtime implementation, qualification,
credentials, readiness, access, private dependencies, and topology remain
framework-managed. Extracted operations must be stable bound function handles.
Portable external packages must propagate dependency metadata through every
maintained execution family without internal provider-runtime imports or namespace
privilege.

Finish function-native scheduling convergence and durable actor qualification.
Use schedule(parameters, closure) as the golden path; lower compatible workflow
cron and one-time execution through the shared schedule graph; keep actor alarms
distinct. Keep the scheduling semantic matrix executable and prove definition,
instance, and occurrence identity; canonical admission; time interpretation;
overlap and fencing; misfire/catch-up; retry and dead letter; pause/update/cancel;
history; and lifecycle parity for every claimed provider. Reject unsupported
lowerings rather than inheriting provider defaults. Close remaining actor
authority gaps and prove the required distributed celld and Kubernetes lifecycle.

Apply the plan's source-surface scheduling disposition exactly. Dynamic
reconcileSchedule() remains the convergence mechanism for product-configured
instances, processor scheduling remains processor lifecycle, actor alarms remain
actor-owned, and raw Kubernetes cron remains an explicit infrastructure escape
hatch. Preserve public compatibility until a proven lowering, documented
migration, and recorded removal release exist; do not collapse these surfaces
merely because they all involve time.
Safely free only Applik8s/TypeKro test capacity on OrbStack when needed; use
Alchemy/TypeKro lifecycle teardown rather than raw resource deletion as the
normal path.

Complete the remaining application-plan, inferred-access, local-runtime,
observability, lakehouse, AWS, Kubernetes, TypeKro/Alchemy, development-agent,
security, migration, performance, and cost requirements. Keep GuestBook, Chirp,
and Agentic Start as the only in-repository acceptance applications. Downstream
consumer products are separate dogfooding exercises and must not enter this public
repository or become release gates.

Treat v0.8 as an implementation-and-convergence release. Do not add unrelated
public capabilities. Add or change public API only when an accepted v0.8 RFP
requires it or an in-repository acceptance application proves that the existing
surface cannot express the accepted behavior. Record its compatibility class,
migration owner, rollback boundary, documentation, and removal of obsolete syntax.

Establish reproducible performance, bundle-size, throughput, latency, memory,
contention, consumer-scaling, and representative cost baselines before claiming
performance maturity. Use fixed fixtures, multiple samples, and noise-tolerant
budgets. Record history and block the relevant maturity claim on unexplained
regressions rather than relying on timing-sensitive single assertions.

Run and repair every locally available deterministic, package-consumer, browser,
Docker, OrbStack, and MiniStack gate. Treat AWS-local only as API-fidelity
evidence. Do not claim real AWS, CloudWatch, Athena, EventBridge Scheduler, or
distributed-provider qualification without their exact live evidence. Keep
scorecard flags false until the corresponding command and environment pass.
Run bounded environment preflight before long live tests, including context,
capacity, storage, controllers, images, network, conflicts, and cleanup ownership;
fail before mutation when prerequisites are not met.

Work according to the dependency graph rather than serializing independent lanes.
Canonical JSON must precede signatures; signed envelopes must precede admission
token migration; canonical admission must precede new ingress lowerings. Once
canonical admission integrates, provider injection, scheduling, actors, targets,
migration/security/performance, and product characterization may proceed in
independent reviewable slices and converge at release qualification.

Do not read, print, overwrite, or commit .env files or secrets. Do not tag,
publish npm packages or images, create a GitHub Release, or deploy to production
until the maintainer explicitly authorizes it. Stop only for a real external
blocker, missing authority, or required maintainer decision; otherwise continue
through the execution plan and report evidence truthfully. End with the exact
maintainer review packet specified by Phase 8, but do not tag or publish it.
```
