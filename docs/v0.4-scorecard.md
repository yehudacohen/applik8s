# v0.4 Executable Scorecard

`bun run check:v04:scorecard` evaluates the v0.4 release line against executable evidence. It validates the longitudinal Tenant Platform graph, stable compatibility labels, transaction authority and effect-isolation metadata, generated processor bounds, performance budgets, adoption docs, and the exact-commit live-evidence release gate.

The reported number is **evidence coverage**, not a subjective maturity rating. `10/10` means every declared check currently has passing evidence; it does not claim that the framework has no remaining product work. The check inventory is committed in `benchmarks/v0.4/scorecard.json`, so adding, removing, or renaming a criterion requires an explicit reviewable change.

The longitudinal graph delta is intentionally small and legible: the v0.3 Tenant Platform has 28 nodes and 13 edges; enabling its v0.4 durable account behavior yields 33 nodes and 19 edges by adding command, event, command-handler, processor, and explicit permission nodes. This is the benchmark for whether authored intent becomes honest generated infrastructure without expanding into v0.5 workflow or v0.6 projection/UI scope.

Performance evidence comes from `benchmarks/v0.4.1/baseline.json` and its checked-in budgets. Use `bun run benchmark:v041:record` to append a comparable machine-stamped history entry, and use the live benchmark separately when PostgreSQL and JetStream throughput evidence is required.
