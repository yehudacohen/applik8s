# v0.5 Executable Scorecard

The v0.5 scorecard measures evidence coverage for the durable task/workflow release boundary. A `10/10` means all declared checks in that dimension pass; it is not a claim that the project has no future maturity work.

Run the local scorecard with:

```sh
bun run check:v05:scorecard
```

Run the full release candidate, including the fresh OrbStack Hatchet/CNPG lifecycle proof, with:

```sh
bun run check:v05:prerelease:orbstack
```

The executable dimensions cover graph architecture, type-directed aliases/signals/errors, bounded result observation, retry-safe task effects, extensible provider registration, the pinned PostgreSQL-only Hatchet provider, worker lifecycle and egress, connection-scoped Kubernetes authority and credential isolation, normalized ownership-safe DNS publication and exact local wakeups, the longitudinal Tenant Platform onboarding/decommissioning story, failure/compensation evidence, release-line-aware CI evidence, performance history, capacity envelopes, bundle budgets, and maintainability ceilings.

Record the environment-tagged v0.5 performance baseline with:

```sh
bun run benchmark:v05:record
```

The baseline records local result-observation throughput/latency/memory, longitudinal graph construction, full workflow build time and bundle sizes, plus portable 1/2/4-replica concurrency/resource/cost envelopes. These are regression signals, not universal production capacity claims.

The live suites prove retry and idempotent effect handling, durable event waits, worker replacement during a wait, resume by signal, correlation propagation, compensation, explicit operator intervention when compensation fails, cancellation, connection-scoped reads and guarded mutations through a separately bound kubeconfig, and TypeKro-first cleanup. Test cleanup refuses to remove the RGD or force-finalize a namespace while owned resources remain.

The pre-v0.6 maintainability gate isolates generated HTTP bundle construction, exposure normalization, graph serialization, compatibility policy, and TypeKro emission planning. Its ratcheted ceilings prevent those concerns from collapsing back into the application or compiler entrypoints. A dependency-direction gate keeps core and browser-facing zones portable, and `@applik8s/testing` exposes deterministic external-provider registration conformance before provider-specific semantic/live suites.

KEDA lowering and HA topology remain preview surfaces until dedicated live scale and failover evidence exists; the supported v0.5 operational path is fixed/manual replicas with bounded slots.
