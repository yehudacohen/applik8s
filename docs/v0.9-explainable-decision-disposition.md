# Explainable domain decisions: library-only disposition

**Decision:** Library only; do not add a first-class `decision()` graph primitive

**Date:** 2026-08-31

**Applies to:** Applik8s v0.9 and the 1.0 public-model freeze

## Outcome

Domain eligibility remains an ordinary typed function. The small
`domainDecision.allow()` / `domainDecision.deny(code, details?)` result algebra
standardizes discriminants and stable reason codes. It does not register a
graph node, grant authority, cache a result, or persist evidence.

The enclosing semantic surface supplies the behavior it actually owns:

- use a plain function for immediate in-process eligibility;
- use a model query or view when the result needs transport, invalidation, or
  live browser reuse;
- call the function inside an operation when it gates a mutation;
- call it inside a Job or workflow when it participates in durable execution;
- record an application event when an eligibility outcome is itself a domain
  fact.

Authorization remains independent and authoritative. An `allowed` domain
result never grants a principal permission to perform an operation. Explanation
details inherit the redaction and visibility policy of the query, operation,
or durable execution that exposes them.

## Prototype findings

The same shape was evaluated for relational refund eligibility, Kubernetes
publication eligibility, and external-risk spending eligibility.

| Dimension | Ordinary function + result algebra | First-class primitive | Finding |
| --- | ---: | ---: | --- |
| Declaration and call-site clarity (20%) | 9.5 | 8.5 | A normal call is the smallest accurate abstraction. |
| Cross-context reuse (20%) | 9.5 | 8.0 | Functions work unchanged inside queries, operations, Jobs, workflows, reconcilers, and tests. |
| Authority separation/redaction (20%) | 9.5 | 7.5 | Enclosing surfaces already own admission and visibility; a primitive risks a second policy system. |
| Staleness/invalidation/evidence (15%) | 8.0 | 9.0 | Queries and durable executions already add these semantics only when needed. |
| Unique graph/runtime value (15%) | 7.0 | 8.0 | Dependency discovery already follows ordinary local helper calls; no distinct runtime was proved. |
| Implementation/migration cost (10%) | 9.5 | 5.5 | The library result is additive and carries no state migration. |
| **Weighted result** | **8.9** | **7.9** | The primitive does not clear the RFP's burden of proof. |

The first-class option's graph advantage is real only when caching,
invalidation, transport, or durability is requested. Those meanings already
have explicit Applik8s nouns. Making every eligibility function a graph node
would add ceremony and invite accidental semantic overlap.

## Canonical example

```ts
import { domainDecision } from "@applik8s/applik8s";

export async function refundEligibility(input: RefundRequest) {
  const order = await Order.require(input.orderId);

  if (order.status !== "paid") {
    return domainDecision.deny("ORDER_NOT_PAID", {
      status: order.status,
    });
  }

  if (order.refundWindowEndsAt < new Date()) {
    return domainDecision.deny("REFUND_WINDOW_EXPIRED");
  }

  return domainDecision.allow();
}
```

When a browser needs a live preview, the application exposes the same function
through `Order.view(...)`. When `RefundOrder(...)` must enforce it, that
operation invokes the same function after its independent authorization check.

## Compatibility consequence

`decision()` is rejected from the v0.9/1.0 foundational vocabulary. The
library-only result algebra is additive and may evolve before 1.0 without a
deployment-state migration because it owns no graph or durable state.
