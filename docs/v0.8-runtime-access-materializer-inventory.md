## Canonical source

`compileApplicationRuntimeAccessPlan()` is the only semantic policy compiler. It
derives source-attributed requirements, intersects selected provider guarantees,
and emits exact local, Kubernetes, and AWS lowerings per execution identity.

The target-neutral enforcement envelope introduced by `RA-1c1` must be a
portable projection of that plan. Target code may translate provider limits, but
must never re-derive semantic authority from application nodes, environment
variables, or already-emitted resources.

## `RA-1c1` implementation boundary

Completed in `RA-1c1a`:

1. Add a versioned, portable runtime-access enforcement envelope to
   `@applik8s/deployment-contract`. It contains target, source graph digest,
   policy digest, execution/node identities, requirement IDs, mechanisms, and
   target identities; it contains no credentials.
2. Embed that envelope in the Kubernetes deployment graph and AWS deployment
   plan. Validation rejects a missing envelope, target mismatch, graph mismatch,
   duplicate execution ownership, wildcard grant, unresolved error diagnostic,
   or digest mismatch before an effect runner is invoked.
Completed in the first bounded `RA-1c1b` sub-slice:

3. Add one parity validator per target. It joins materialized ServiceAccounts,
   RBAC and Secret projections plus IAM roles, task-role references, and declared
   private-peer edges back to envelope executions and requirement IDs.
4. Replace AWS's first-role-by-node lookup and separate statement appenders with
   an explicit workload enforcement record. Reject multiple execution policies
   unless their union is deliberate, deterministic, and recorded on that exact
   workload.
5. Make Kubernetes projection versus API-read semantics explicit before
   materializing Secret access. Do not retain unused Secret RBAC merely because
   an environment projection exists.

Still active in `RA-1c1b`:

6. The provider-neutral private-peer record, checked legacy projection, and
   maintained Kubernetes endpoint descriptors are complete at `6f3a8d4`.
   Classify DNS/external egress, then materialize and validate NetworkPolicy and
   SecurityGroup rules from the authoritative record.
7. Add explicit provider-owned workload descriptors for direct TypeKro
   compositions so their access is neither unplaced nor inferred from opaque
   rendered output.
8. Record ECS execution-role Secret projection separately from application task
   authority and validate both against the synthesized CloudFormation template.

## Required deterministic evidence

- the same source graph and selected provider guarantees produce byte-identical
  enforcement envelopes across repeated compilation;
- removing, widening, or misbinding one Kubernetes RBAC rule, Secret projection,
  AWS statement, role attachment, or declared private-peer edge fails before
  mutation with the requirement and execution identity;
- two executions on one semantic node cannot make a workload select an arbitrary
  first role or ServiceAccount;
- a sibling runtime receives neither another runtime's credential projection nor
  its role/network authority;
- unsupported provider guarantees and target ceilings remain named diagnostics,
  not synthetic wildcard grants;
- the envelope, deployment graph/AWS plan, and ApplicationPlan share the same
  source-graph and policy digests.

The corresponding NetworkPolicy, rendered SecurityGroup, provider-owned workload,
and ECS bootstrap-secret cases remain required before this list is complete.

## Evidence boundary

Passing `RA-1c1` proves deterministic target lowering and pre-mutation refusal.
It does not prove Kubernetes admission/denial, IAM behavior, security-group
behavior, drift repair, or production credentials. Those remain `RA-1c2`,
`RA-1c3`, and `RA-1d` claims with independently labelled live evidence.
